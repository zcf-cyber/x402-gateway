# AI Assisted Development Pipeline (OpenHands + Qoder)

## 🧠 项目简介
本项目实现了一套 AI 辅助开发流水线，通过分离 AI 自动开发与人工审查，实现：
- 高效率代码生成（OpenHands）
- 高质量代码控制（Qoder + 人类）
- 安全隔离（分支 + 测试 + 约束）

---

## 🏗️ 架构概览
A电脑（Human + Qoder） → PR Review → main  
B电脑（OpenHands） → ai-dev → dev → main

---

## 🎯 核心设计理念

### 1. 分离职责
- AI（OpenHands）：自动开发  
- 人类（Qoder）：审查 / 决策  
- Git：隔离与合并  

### 2. 核心原则
- AI 不允许直接修改主分支  
- AI 不参与最终决策  
- AI 仅作为受限执行单元  
- 人类作为最终 Gatekeeper  

---

## ⚠️ 关键问题
- AI 跑偏（目标驱动）  
- PR 过大不可控  
- 测试不足  
- 成本失控  

---

## 🔧 解决方案：边界控制

### 四层边界模型

1. 文件级边界  
仅允许修改指定目录  

2. 行为边界  
禁止重构 / 改接口  

3. 依赖边界  
禁止新增依赖  

4. PR 边界  
≤3文件，≤200行  

---

## 🧩 OpenHands 任务模板

任务：
实现 <功能>

约束：
- 仅允许修改指定目录
- 禁止新增依赖
- 禁止修改接口
- 限制 PR 大小
- 必须通过 pytest

---

## 🔄 开发流程

1. OpenHands 开发（受限）
2. 自动测试（pytest + lint）
3. 提交 PR（ai-dev → dev）
4. Qoder 审查
5. 合并到 main

---

## 🧪 测试策略
- pytest
- lint（ruff/eslint）
- type check

必须自动化，不允许仅手动测试

---

## 💰 成本控制
- 小任务拆分
- 限制上下文
- 限制改动范围

---

## 🧠 系统定位
AI = 受限执行单元（初级工程师）

---

## 🚀 进化路径
阶段1：分支隔离  
阶段2：边界控制 + 测试  
阶段3：多模型 + 网关  

---

## 📌 总结
让 AI 写代码很容易，让 AI 在受控环境中稳定产出才是关键。
